# BE06 — Rebuild và compare tại cùng block H

BE06 thực hiện FR15 và kiểm tra TC12 bằng database đích mới. Lệnh đọc một
manifest deployment đã xác minh, chain ID/RPC và H cụ thể; lấy governance
metadata từ manifest cùng state tại H; áp dụng migration 001–003; gọi lại BE03
ingestion/checkpoint rồi BE04 projection. Database tham chiếu chỉ được đọc.
BE06 không đổi `DATABASE_URL`, API hoặc database BE05.

Đọc [FR15 và TC12](requirements/DAO_Budget_Simulator_Requirements_Nhom_4.md)
trước khi nghiệm thu. Manifest phải đến từ TV4 handoff đã audit, gồm GOV và bốn
contract BE03, địa chỉ, deployment block, ABI version, chainId và source commit.
BE06 kiểm tra K canonical, bytecode ở deployment block và H, Governor token /
Timelock / Treasury / BUD linkage, Governor clock, governance settings và
Treasury balance tại hash H. Proxy hoặc runtime bytecode thay đổi giữa hai mốc
bị từ chối. RPC phải hỗ trợ `eth_getLogs`, historical `eth_call` và block-hash
tag EIP-1898 với `requireCanonical`; không có fallback sang `latest`.

## Cấu hình và chạy

Không dùng `.env` tự động. Sao chép [manifest mẫu](../indexer/config/be06.manifest.example.json)
chỉ để xem schema; thay bằng `handoff.json` đã xác minh và không dùng giá trị
`REPLACE_*`. Tạo sẵn một database tham chiếu có BE04 publication đúng H/hash và
một database đích PostgreSQL mới, rỗng, cùng cluster hoặc cluster riêng. Không
đặt database BE05 đang chạy làm đích.

```bash
export RPC_URL=http://127.0.0.1:8545
export BE06_MANIFEST_PATH=/absolute/path/to/handoff.json
export BE06_REFERENCE_DATABASE_URL=postgresql://be06_readonly@127.0.0.1:5432/dao_reference
export BE06_TARGET_DATABASE_URL=postgresql://be06_rebuild@127.0.0.1:5432/dao_rebuild_new
H=123456

npm run be06 -- rebuild --manifest "$BE06_MANIFEST_PATH" --at "$H" \
  --output reports/be06-rebuild.json
npm run be06 -- export --manifest "$BE06_MANIFEST_PATH" --at "$H" \
  --database reference --output reports/be06-reference-normalized.json
npm run be06 -- export --manifest "$BE06_MANIFEST_PATH" --at "$H" \
  --database target --output reports/be06-rebuild-normalized.json
npm run be06 -- compare --manifest "$BE06_MANIFEST_PATH" --at "$H" \
  --json-output reports/be06-compare.json --summary-output reports/be06-compare.md
```

`K` lấy từ `confirmations`/`confirmationPolicy.depth`, mặc định 2. `H` phải là
số block thập phân cụ thể và không được vượt `head-K`. Rebuild phải kết thúc với
checkpoint raw và publication BE04 đúng H/hash; block trống vẫn được index và
state được tính theo clock tại H. Target phải rỗng trước migration. BE06 không
DROP/TRUNCATE và không tạo database. Rebuild lỗi sau khi ghi có thể để lại
database một phần; giữ nguyên để chẩn đoán rồi provision database đích mới cho
lần chạy tiếp theo.

Export yêu cầu publication BE04 hiện có đúng H/hash và scope. Không lọc các bảng
projection mới nhất theo block để dựng giả lịch sử. Nếu reference chưa publish
đúng H, hãy tạo publication tham chiếu tại H bằng tiến trình BE04 riêng rồi mới
compare; không có publication thì compare trả lỗi.

| Lệnh | Exit code |
| --- | --- |
| `rebuild` | 0 khi raw checkpoint và projection đạt chính xác H/hash; 1 khi RPC, K, manifest, DB hoặc projection không đạt |
| `export` | 0 khi xuất được normalized JSON; 1 khi DB không có publication H/scope hợp lệ |
| `compare` | 0 khi mọi trường normalized bằng nhau và chain cross-check qua; 2 khi có mismatch; 1 khi tham số/thiết lập không hợp lệ |

Report ghi path và giá trị reference/rebuild khác nhau. File output được tạo mới
với quyền owner-only, không overwrite file có sẵn. Không truyền RPC URL chứa
credential hoặc in URL ra log; cấp database role tham chiếu chỉ có quyền đọc.

## Phạm vi dữ liệu và semantics

Normalize gồm deployment scope, H/hash/time, governance config, proposal ID,
requestId, raw description bytes/text, targets/native values/calldata, event
coordinates, state/vote/quorum, vote reason/params, operation ID/ETA/lifecycle,
BUD Transfer, BudgetDisbursed link, tổng vào/ra/số dư, decode warnings và số
ancillary events được BE04 bỏ qua. Bỏ internal deployment/row ID, UUID revision,
ingest/publish time và API cache. Business IDs không bị gộp; requestId zero hoặc
được dùng lại giữa nhiều proposal vẫn tách khỏi proposalId và operationId.

Transfer của BUD là nguồn tính dòng tiền; BudgetDisbursed chỉ liên kết Transfer.
Compare đối chiếu `state()`, `proposalVotes`, `quorum(snapshot)`, Timelock
`getTimestamp`, Governor clock/linkage và `balanceOf(Treasury)` tại đúng hash H
cho cả reference lẫn rebuild. BE03 raw warnings được giữ nguyên. 16 bootstrap
ancillary unknown đã biết phải còn `decodeComplete=false`; unknown business hoặc
malformed log vẫn chặn publication. BE05 API/cursor semantics không đổi.

## Kiểm thử

```bash
npm run typecheck
npm run build
npm run test:be06
npm run test:be06:db
npm run test:be06:live -- --output reports/be06-live.json --be06
```

DB suite cần hai database rỗng, tách biệt qua
`BE06_TEST_ISOLATED=1`,
`BE06_TEST_REFERENCE_DATABASE_URL` và `BE06_TEST_TARGET_DATABASE_URL`. Live
runner cần một database nguồn trống `be04_live` do `be04_test` sở hữu cùng hai
database đích rỗng, loopback; đặt `BE04_LIVE_ISOLATED=1`,
`BE04_LIVE_DATABASE_URL`, `BE06_LIVE_ISOLATED=1`,
`BE06_LIVE_TARGET_DATABASE_URL` và
`BE06_LIVE_ADVANCED_TARGET_DATABASE_URL`. Nó tự deploy trên Anvil mới, ghi
publication tham chiếu tại H, rebuild hai target độc lập, tạo một BUD Transfer
sau H, xác nhận H/hash vẫn cố định và event mới không xuất hiện trong hai
target. `--output` và file manifest bên cạnh phải chưa tồn tại.

Có thể thay Docker/PowerShell wrapper bằng PostgreSQL local mới, cô lập, có
loopback khi wrapper không có sẵn; ghi rõ môi trường thực chạy trong evidence.
Không coi raw replay hoặc gọi `--project` trong cùng database là FR15.

Reorg rollback/retry tự động thuộc BE07; benchmark nghiệm thu thuộc BE08. TV4
cần nghiệm thu độc lập FR15 rebuild/compare. TV1 cần xác nhận đối chiếu
on-chain; việc chạy local không hoàn tất peer review.

BE07: database rebuild mới áp dụng thêm migration 004/005 và nhận serving gate. Recovery/retry hiện có trong [BE07](be07.md); compare vẫn bỏ runtime timestamps/revision và kiểm tra dữ liệu tại cùng H/hash.
