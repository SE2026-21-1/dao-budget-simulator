- Dòng 12–20: run dùng running ref để chống gọi chồng; trước mỗi run set phase signing, setHash(null), xóa error; sau send lưu submitted hash và gọi waitForReceipt(submitted).

- Dòng 19: requestId được khởi tạo bằng useState(newRequestId), nên ổn định qua rerender trong cùng mount.
- Dòng 39–54: mỗi lần submit build cùng payload từ form/requestId, sau đó truyền callback gửi propose vào transaction.run; callback receipt mới đặt submittedId.

OpenZeppelin Governor provenance:
- Candidate HEAD gitlink lib/openzeppelin-contracts points to c64a1edb67b6e3f4a15cca8909c9482ad33a02b0. Read the matching initialized submodule at the user's clean dao-bt3-vt062 clone; its submodule status matches that gitlink.
- lib/openzeppelin-contracts/contracts/governance/Governor.sol lines 304–318 computes proposalId from targets, values, calldatas and keccak(description); if _proposals[proposalId].voteStart is already set, it reverts GovernorUnexpectedProposalState before state write/event.
- Therefore, the exact unchanged proposal payload does not produce a second ProposalCreated event: H2 is still an unnecessary wallet/on-chain transaction attempt and is expected to revert. Different description/actions can yield a different proposalId even with reused requestId; that is outside the unchanged-draft test and remains protected from duplicate successful payout only by Treasury.paidRequests.
